# Klick'r - Smart AutoClicker

Android 可视化自动化工具。根据屏幕上的图片、文字、数值和颜色判断当前状态，再执行点击、滑动、等待或子流程，处理游戏与应用中的重复操作。

[下载正式版](https://github.com/slobys/Smart-AutoClicker/releases/latest) · [使用文档](documentation/reliability-and-diagnostics-zh.md) · [更新记录](https://github.com/slobys/Smart-AutoClicker/releases) · [反馈问题](https://github.com/slobys/Smart-AutoClicker/issues)

支持 Android 7.0（API 24）及以上。通过界面配置条件与动作，不需要编写代码；脚本需要按目标应用和设备自行配置。

## 功能概览

从固定位置点击，到识别画面后执行多步操作，可以按任务需要组合以下能力：

| 功能 | 可以做什么 |
| --- | --- |
| 点击与滑动 | 配置固定坐标或识别位置点击、长按、滑动、等待和重复执行 |
| 画面识别 | 使用图片、文字、数值、颜色条件；通过 AND / OR 组合多个判断 |
| 流程控制 | 用计数器记录进度，按时间或状态触发事件，调用子流程并返回 |
| 等待与确认 | 等待目标出现、消失或画面变化；点击后确认结果；滑动查找目标并限制次数 |
| 场景管理 | 创建分组、批量归组、收藏、搜索，以及场景备份和导入 |
| 路线录制（实验） | 数字坐标或固定方向小地图定位，录制、校准和回放；支持固定摇杆短按移动、轨迹预览及“执行路线”动作 |
| 悬浮控制 | 贴边收起、弧形快捷菜单；关闭调试窗口后仍可使用暂停入口 |
| 调试与排错 | 查看实时调试信息，设置事件断点、执行事件级单步；查看运行历史、动作耗时与失败原因 |
| 长时间运行 | 限制图片缓存与报告占用，清理截图和检测资源，记录内存采样与可用的系统退出原因 |

### 选择哪种场景

根据任务是否需要识别画面，选择对应类型：

- **简单场景**：按配置顺序重复点击、滑动，适合位置固定、不需要判断画面的操作。
- **智能场景**：条件满足后才执行动作，适合需要识别按钮、等待界面或按进度切换步骤的任务。

智能场景包含多个事件，每个事件定义“什么时候执行”和“执行什么”。子流程复用某个事件的动作，执行一次后返回调用位置；计数器可在流程间共享数值。

### 几个使用例子

这些组合可以作为配置脚本的起点：

- 打开背包后，用“点击后确认”等待背包界面出现，再执行后续动作。
- 在任务列表中滑动查找目标，找到后停止滑动；达到次数上限仍未找到时返回失败。
- 把“打开菜单 → 进入指定页面”的重复动作放入子流程，供多个事件调用。
- 每完成一轮任务就让计数器加 1，达到设定次数后触发结束逻辑。

点击后确认、智能滑动查找等功能需要手动启用，配置位置与失败处理规则见[使用文档](documentation/reliability-and-diagnostics-zh.md)。

## 下载与安装

本仓库的安装包统一发布在 [GitHub Releases](https://github.com/slobys/Smart-AutoClicker/releases/latest)：

1. 打开最新正式版，展开 **Assets**（附件列表）。
2. 不确定设备架构时，下载文件名以 `universal-release.apk` 结尾的通用包。
3. 在 Android 设备上安装 APK，按应用提示完成权限授权。

发布页也提供 `arm64-v8a`、`armeabi-v7a`、`x86` 和 `x86_64` 架构包，以及用于核验文件的 `SHA256SUMS.txt`。通用包与对应架构包的功能相同。

### 升级已有版本

升级前先导出场景备份，再安装新版本：

- 本仓库的旧正式版沿用同一发布签名，可直接覆盖升级。**不要为升级而卸载应用或清除数据。**
- 上游或应用商店版本可能使用不同签名；遇到安装冲突，先确认备份完整，再处理版本迁移。
- 独立 Debug 测试版使用 `.debug` 包名，与正式版不共享场景数据，需通过备份导出、导入转移。

## 第一次使用

建议先用内置教程熟悉条件和动作，再配置自己的任务：

1. **完成授权**：按提示开启无障碍服务和悬浮窗权限；启动智能场景时允许屏幕捕获。无障碍服务用于执行操作，屏幕捕获用于识别画面。
2. **体验教程**：在“场景”首页点击右上角的学士帽图标，练习图片、文字、数值、颜色条件，以及计数器和动作。
3. **创建场景**：回到“场景”首页，点击右下角 **＋**，填写名称，选择“简单”或“智能”，保存。
4. **配置任务**：简单场景添加操作；智能场景添加事件，再设置条件和动作。从一个条件、一个动作开始，逐层保存后测试。
5. **运行与调整**：在场景卡片展开操作，启动场景，再使用悬浮菜单控制运行。先验证少量循环，确认识别和点击正确后再增加次数。

涉及购买、提交或其他不可撤销操作时，先在不会产生实际损失的界面测试。界面缩放、动画和网络延迟都可能影响执行结果。

## 排错与使用文档

遇到问题时，先区分“条件没有识别到”“动作执行失败”和“应用进程退出”，再检查对应信息：

| 遇到的情况 | 建议先检查 |
| --- | --- |
| 图片、文字或数值识别不到 | 检测区域是否正确，目标是否被遮挡，字体、缩放或动态背景是否变化 |
| 点击了但界面没变化 | 无障碍服务是否可用、点击位置是否正确；页面加载时可配置等待或点击后确认 |
| 界面还没加载就执行下一步 | 给动作留出等待时间，或使用目标条件确认下一步是否就绪 |
| 应用退出，悬浮图标一起消失 | 重新打开应用，从“场景 → 更多选项 → 运行历史”导出诊断 ZIP |

运行历史记录动作结果、耗时和失败原因，并保留有限数量的失败截图。诊断包还包含可用的内存采样与系统退出记录；这些数据保存在本机，不自动上传。分享前请检查角色名称、聊天等私人信息。

报告问题时，请附上应用版本、Android 版本、设备或模拟器型号、发生时间、复现步骤，以及可用的诊断包。云手机还请注明平台名称。

相关入口：

- [稳定执行与诊断指南](documentation/reliability-and-diagnostics-zh.md)：点击后确认、智能滑动查找、运行历史与内存诊断。
- [路线录制与回放](documentation/route-recorder-zh.md)：数字坐标／小地图模式、摇杆校准、场景调用和安全测试（开发分支新增，旧正式版不含此入口；不支持随机地图自动探索）。
- [版本说明](documentation/releases)：每版改动、验证结果和适用范围。
- [问题与功能建议](https://github.com/slobys/Smart-AutoClicker/issues)：提交复现信息或描述希望解决的任务。

识别效果和长时间运行情况取决于实际画面与设备环境。内存优化不能阻止系统或云手机平台回收进程，自动化测试也不能代替真实设备上的长期验证。

## 开发与构建

项目使用 Kotlin、C++ 和多模块 Gradle。构建需要 JDK 21、Android SDK 37、NDK 28.2.13676358 与 CMake 3.22.1；依赖版本见 [libs.versions.toml](gradle/libs.versions.toml)。首次构建需要联网下载依赖和原生库资源。

主要目录：

```text
smartautoclicker/   应用入口、服务、场景列表与运行历史
core/common/       截图、位图、无障碍与悬浮窗等公共能力
core/smart/        数据库、识别、流程执行与调试
feature/           场景编辑、备份、教程等功能界面
build-logic/       Gradle 构建约定
documentation/     使用指南与版本记录
```

使用仓库自带的 Gradle Wrapper 构建测试版，并运行单元测试与 Lint 检查：

```shell
./gradlew :smartautoclicker:assembleFDroidDebug
./gradlew testFDroidDebugUnitTest lintFDroidDebug
```

Windows PowerShell 中将 `./gradlew` 换成 `.\gradlew.bat`。连接 Android 设备或模拟器后，可运行图片与文字识别测试：

```shell
./gradlew :core:smart:detection:connectedFDroidDebugAndroidTest
```

测试流程见[测试工作流](.github/workflows/execute-tests.yml)。正式版通过[发布工作流](.github/workflows/release.yml)验证、构建与签名；`fDroid` 是构建变体名称，不表示已在 F-Droid 商店上架。请勿提交签名私钥、密码、个人诊断包或设备数据。
