# 稳定执行与诊断功能使用说明

本文介绍执行可靠性与诊断功能：第 1–6 节说明 v4.0.5.23 引入的能力，第 7 节说明 v4.0.5.24 的内存稳定性优化，第 8 节记录后续的手势与暂停修复。点击后确认、智能滑动查找等可选功能默认关闭；普通点击、普通滑动与已确认的贴边悬浮菜单保持原有用法。未新增第三方运行时依赖。正式版安装包与更新说明见 [GitHub Releases](https://github.com/slobys/Smart-AutoClicker/releases/latest)。

## 1. 点击后确认：避免按钮没生效就继续，也避免重复消费

适合：打开背包后确认背包界面出现、领取奖励后确认完成提示、提交任务后确认下一步。

1. 打开一个智能场景，创建一个屏幕事件，命名为“背包已打开”。
2. 在它的“条件”里添加背包界面独有的图片、文字、数值或颜色条件。
3. 若这个事件只用来确认、不希望自动触发，把“初始状态”关闭。事件编辑器仍要求至少一个动作才能保存，可以放一个短暂停；确认功能不会执行这个动作。
4. 打开主事件 → 动作 → 点击，配置原有点击位置。
5. 向下滚动到“点击后确认”说明下的“关闭 · 保持普通动作”，点击后选择“背包已打开”。
6. 填“确认超时”，例如 `5000` 毫秒，保存动作、事件和场景。

执行效果：点击一次 → 采集新画面 → 连续两帧满足目标条件 → 继续后面的动作。

确认超时、目标丢失或其他确认失败时，停止当前场景，不自动重复这个点击，防止购买、提交等操作重复执行。不存在的确认目标会在点击前被拒绝。超时范围为 400–300000 毫秒；游戏加载建议预留 3–10 秒。若目标一开始就存在，此功能只能证明点击后它仍存在，不能证明发生了页面切换，应选择真正代表完成状态的条件。

## 2. 智能滑动查找：找到了就停，不无限滑动

适合：在任务列表里找到“师门任务”、在道具列表里找某个图标、向下翻页寻找指定按钮。

1. 在同一智能场景中创建目标屏幕事件，例如“找到师门任务”，配置目标条件。
2. 建议关闭它的“初始状态”，避免与主事件争抢执行；主流程仍能使用它的条件。
3. 打开主事件 → 动作 → 滑动，先选择起点、终点和滑动持续时间。
4. 向下滚动，在“智能滑动查找”说明下点“关闭 · 保持普通动作”，选择目标事件。
5. 设置“每次滑动后等待”，例如 `1500` 毫秒；设置“最多滑动次数”，例如 `5`。保存。
6. 若找到后还要点击，在此动作后加“事件控制与子流程”，选择目标事件的“执行一次”。目标事件里配置“点击识别位置”。

执行效果：先检查 → 没找到才滑动 → 等动画结束 → 重新截图检查 → 找到后两帧确认并返回。

开始前就找到时，不滑动。最后一次滑动后仍会检查。达到上限仍未找到、截图不可用或手势失败时，会中断本事件的后续动作；同一事件连续失败 3 次会触发场景保护停止。该功能不会自动执行目标事件的动作。最多 1–50 次；每次等待 200–30000 毫秒。动画较长时不要把等待设置得太短。

图片、文字、数值和颜色均沿用目标事件原有的条件规则，不是另一套识别引擎。

## 3. 运行历史与诊断包

入口：主界面“场景” → 右上角“更多选项”（三个点） → “运行历史”。

- 点一次运行记录，查看事件、动作、成功/失败/取消/超时/跳过、耗时与原因。最新动作显示在前面。
- 点“导出诊断 ZIP”，在系统文件保存窗口选择位置。
- ZIP 包含 `session.json` 与可用的失败截图，可交给开发者排查。截图可能包含游戏角色、聊天等信息，分享前请检查。
- 数据仅保存在本机，不自动上传；最多保留 20 次运行，每次最近 500 个已完成动作、最多 5 张失败截图，总量约束为 64 MiB。
- 失败立即落盘；成功动作每 16 条批量写盘、正常停止时补齐。系统强杀时最多可能丢失末尾 15 条成功动作。
- 这是动作执行历史，不是每一帧 OCR 候选结果，也不是游戏录像。外部取消正在执行的动作时，未完成动作可能没有独立历史行。磁盘故障不会因为写诊断而让脚本崩溃。

## 4. 本次修正的执行问题

- 截图缺失或条件不可用不再误判为“目标已消失”；画面稳定确认遇到缺帧会重新累计。
- 子流程使用新截图解析识别位置，不再借用主流程点击前的旧画面。
- 移除子流程外层 60 秒超时和长等待 10 分钟截断；手势和等待仍有自己的边界，循环调用/最多 8 层保护保留。
- 连续失败按整个事件统计，前面的成功暂停、其他事件成功不再清除这个事件的连续失败次数。
- 缺失的计数器操作数不再按 0 比较；无效条件不会证明目标消失。OR 中另一个有效条件仍能正常成立。
- Android 拒绝手势、返回/主页操作、文本输入或启动应用时，向上返回真实失败。通知成功仅代表已进入发送队列，不保证系统允许显示或用户看到了通知。
- 复制等待/备用事件/确认目标时检查引用，缺失时提示选择替代事件；导入新场景时正确转换临时事件 ID。
- 数据库 26→27 只增加可空字段，旧脚本默认关闭新功能；旧备份保留智能等待与断点配置。
- 正式发布工作流增加单元测试、Lint 和识别仪器测试门禁；远程执行结果以对应版本的 GitHub Actions 记录为准。

## 6. 修改位置

- `core/common/actions`：Android 动作成功/失败返回值与回归测试。
- `core/smart/processing`：动作执行、等待、子流程截图、条件校验、失败保护、运行历史与回归测试。
- `core/smart/domain`、`core/smart/database`：可选动作配置、事件引用、复制导入、旧备份兼容、数据库 27 与迁移测试。
- `feature/smart-config`：点击/滑动配置入口及缺失引用修复界面。
- `smartautoclicker/.../scenarios/history` 和场景菜单：运行历史列表、详情、诊断 ZIP 导出。
- `.github/workflows`：发布前复用测试门禁。
- `README.md` 与本文：中文说明入口、功能边界和验收结果。

## 7. v4.0.5.24 内存稳定性优化（2026-09-27）

此前通过独立测试版 `4.0.5.23-memory-20260927` 验证的优化纳入 v4.0.5.24 正式版。保留原识别分辨率、阈值、点击坐标和计数器规则，重点降低长时间运行的额外内存占用：

- 图片模板缓存改为 Java 最大堆的 1/8，且不超过 32 MiB；截图使用独立的单个复用缓冲，不会随模板缓存淘汰而反复创建。关闭截图后解除缓冲引用，不提前回收仍被识别使用的图片。
- 调试报告改为单个后台写入任务；等待队列最多 64 条、序列化数据合计 512 KiB，单条最多 128 KiB。另预留一个结束任务位置。单事件明细也有限额。
- 磁盘过慢造成队列超限时，取消本次调试报告，保留脚本运行、实时调试与独立运行历史。不会丢掉部分计数器变化后伪装成完整报告。
- 每次运行立即采样一次，此后约每 30 秒采样，保留最近 120 条内存记录并落盘。记录仅包含本应用内存和设备总内存状态，不自动上传，不采集其他应用进程列表。
- 诊断包 `session.json` 的 `memorySamples` 包含 PID、Java/Native 内存、PSS、模板与截图缓存、系统可用内存；历史系统退出记录带有可读原因，如 `LOW_MEMORY`。`diagnostics.json` 中包含可用的调试报告状态，如 `completed`、`queue_overload`、`io_failure`、`size_limit`。

这些限制降低应用自身的内存压力，但不能保证云手机在系统内存严重不足时不杀进程。系统退出记录要按时间和 PID 对应运行记录，不能把历史退出原因直接套到最近一次正常结束的运行上。

发布准备阶段已通过 1037 项单元测试。独立 Debug 测试包在 Google 官方 Android 12L 平板模拟器中完成 5000 次计数器/颜色条件循环，调试窗口和报告开启，约 4 分 56 秒自然结束，运行采样 PSS 约 110–131 MiB；中途注入内存回收通知后继续运行。这不是实际内存耗尽复现，也不是云手机两天连续运行或 OCR 动态背景准确性验证。正式发布由工作流重新验证标签源码并构建签名 APK。

正式版沿用本仓库此前正式版的包名与签名，升级前请备份场景，直接覆盖安装；此前独立测试版仍是另一个应用，场景需通过备份转移。请勿为升级而卸载应用或清除数据。完整变化见 [v4.0.5.24 发布说明](releases/v4.0.5.24.md)。

## 8. 手势结果与加载期间暂停（2026-10-03）

### 防止结果不明时重复操作

此前把“Android 明确拒绝派发”和“已派发但没有收到回调”都当作可重试错误。现在区分处理：

- 只有系统明确返回未派发，才允许原有的一次重试。
- 回调超时或派发异常时，触摸可能已经生效，不再自动补点。智能场景立即停止本轮及后续运行，不等待连续失败三次；简单场景也停止剩余重复次数。
- 迟到的回调不会重新启动已结束的等待，用户取消等待也不会触发补点。

这种保护不能撤销已经交给 Android 的触摸，也不能单凭回调证明游戏已经完成购买、提交等操作。关键操作仍建议配置“点击后确认”。若因结果不明停止，先确认游戏当前状态，再手动恢复。

### 暂停覆盖尚未完成的加载

- 智能场景的每次启动带有独立请求标识。暂停、关闭、切换场景或新的启动会使旧请求失效；即使旧数据库读取稍后完成，也不能再次启动。
- 简单场景显式管理加载任务与执行任务，暂停时一起取消。旧任务迟到的结束回调不能停止新一轮运行。
- 通知栏、悬浮菜单、音量键暂停与运行中切换不再只检查“已经运行”，也会停止尚在加载的任务；动作测试同样受保护。悬浮菜单启动加载时显示暂停状态，第二次点击取消启动，不再叠加启动请求。
- 取消旧的自动停止计时器，避免上一轮的计时器误停新一轮。

### Windows 构建与验证

使用 `scripts/build-windows.ps1` 校验 JDK 21，并通过临时 ASCII 盘符执行 Gradle，避免中文源码目录触发 CMake/NDK 路径问题。脚本结束时恢复当前进程的环境变量并撤销自己创建的盘符；不改全局 Java 配置，不复制或移动仓库。

```powershell
.\scripts\build-windows.ps1 -JavaHome 'C:\path\to\jdk-21' -Tasks 'testFDroidDebugUnitTest',':smartautoclicker:lintFDroidDebug',':smartautoclicker:assembleFDroidDebug','--continue'
```

新增回归覆盖手势超时、异常、迟到回调、取消等待，以及加载期间暂停/关闭/切换、快速重启、旧任务结束和自动停止计时器。受控测试已在旧实现上复现重复派发与暂停后启动；这些测试不等同于真机复现。本次不改数据库、识别算法或悬浮菜单布局，也未新增第三方运行时依赖。

主要修改位置：`core/common/actions` 的手势结果与重试、`core/smart/processing` 的启动保护和动作停止、`core/dumb` 的加载与重复执行、`feature/smart-config` / `feature/dumb-config` 的暂停入口、`smartautoclicker/localservice` 的服务生命周期，以及 `scripts/build-windows.ps1`、README 和对应回归测试。

本地验收结果：132 个测试套件、1265 项单元测试全部通过，零失败、零跳过；应用 Lint 零错误，保留 16 项既有警告；完整 FDroid Debug APK 构建成功。错误 JDK 的预检查、构建脚本语法和 `git diff --check` 均通过。本轮没有连接 Android 设备，未做真机或游戏长时间运行验证；提供的是独立包名的 Debug 测试包，不覆盖正式版，也不等同于已发布新的正式版本。
