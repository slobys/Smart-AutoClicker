# 路线转弯与返程验证（2026-10-04）

本轮针对 A/B 含义不清、短转弯丢失、过早转向、返程接入受限和长时间后定位失败修改。路线仍是实验功能，不是地图寻路器。

## 已确认的原因与改动

- 录制曾丢弃距离上一点不足 3 单位的读数，相隔 2 单位的小拐弯可能根本没保存。现在每次采样间隔为 200 毫秒加识别耗时，位移至少 1 单位即保留；总量仍限 2000 点，保留草稿与定位丢失保护。
- 原有 2 单位到达范围可能让角色尚未走到小拐点就转向。起点、拐点、终点现在最多允许 1 单位误差，且需要两次新画面中的站稳确认。只合并短直线，不把多个拐弯连成斜线。
- A/B 是两个局部方向的校准样本，不是录制路线的起终点或要持续识别的游戏物体。录制不会派发 A/B 点击。校准现在观察移动过程，拒绝没有移动、明显绕路、回退或平行的样本，并在界面显示屏幕偏移与实际位移。
- 返程可以从已录道路中途接入，只反向经过接入位置之前的路径点，不再要求先走到终点。中途接入距离最多 1.5 单位；相似平行路段无法明确区分时不盲走。终点附近原有的有限接近范围保留，不代表附近没有障碍。
- 小地图返程先在至多 32 个已保存关键帧中重新定位；运行后恢复相邻关键帧搜索与跳变保护。暂停恢复不会重新定义起点或学习新返程路线。
- 原生 `ScreenImage` 曾根据首次诊断标识设置进程级 600000 毫秒期限。以 `route:ID` 开始识别可能触发期限，之后不更新屏幕图像；新检测器的 ROI 保持 `0×0`，从而把有效地图误报为不匹配。本轮模拟器日志已出现该现象。已移除这一图像抑制逻辑及其唯一辅助头文件，诊断标识不再决定识别是否工作。

不改变路线文件 v1/v2 格式，不迁移数据库，不添加依赖，不改变全局 JDK。

## Google 官方模拟器实际链路

专用只读 `Small_Tablet`，Android 12 / API 32，1920×1200；只安装 debug APK 和仓库的本地测试地图。没有打开腾讯模拟器、应用宝或真实游戏。

测试地图 `corridor` 模式模拟连续走路、镜头平移和窄路碰撞，路线上包含两段仅 2 单位的小转弯。使用真实 MediaProjection 截图、原生数字识别和 Android 无障碍手势，不是仅调用假 `RoutePort`。

| 测试 | 已观测结果 |
| --- | --- |
| 7 点窄路前进 | `(100,100)` 到 `(126,128)`，10 次手势，依次经过所有拐点；无 `blocked`，界面确认终点 |
| 从终点完整返回 | 再增加 10 次手势，按反向拐点回到 `(100,100)`；无 `blocked`，界面确认起点 |
| 从 `(114,110)` 中途返回 | 5 次手势，经 `(114,102) → (112,102) → (112,100) → (100,100)`，不前往终点；无 `blocked`，界面确认起点 |
| 实际录制并回放 | 最终 APK 实际录下 39 点，包含 `(112,100) → (112,102) → (114,102)` 小转弯，完成状态为真；重置后 10 次手势到 `(126,128)`，无 `blocked`，界面确认终点 |

前三项先验证路线控制改动，发现并修复原生期限后，又通过最终 APK 的实际录制与回放检查完整链路。39 点原始路线及 A/B 校准保存在新 ID 中，原 7 点夹具未被覆盖。620 秒长测验证原生帧入口，不等同于连续十分钟真实游戏寻路测试。

每个用例以 `RouteCase` 日志标记区分；测试前手动点击造成的碰撞不计入回放结果。截图与日志保存在本机 `artifacts/route-20261004-*`，不把模拟器截图、APK 或模型提交进源码仓库。

## 使用与验证边界

- 旧路线漏掉的转弯无法从现有文件补回，请重新录制。旧的错误 A/B 也无法凭两个结果追溯当时是否绕路，请在附近空地重新校准。
- 校准只要求眼前一小段地面直接可达；录制可以沿有墙、有拐弯但实际可通行的道路走。没有采到的快速绕路不保证被检测到。
- 转弯录制时应放慢，不能保证每 200 毫秒都完成一帧 OCR。坐标丢失不会当作零坐标继续移动。
- 返回不是任意位置自动寻路，未知障碍、单向门、传送、跳崖、需重新开门的路段仍不适用。
- 本轮窄路端到端测试针对数字坐标和地面点击。真实游戏、不同手机、摇杆死区及小地图定位仍需针对性验收；不能把模拟器通过写成所有游戏已稳定。
