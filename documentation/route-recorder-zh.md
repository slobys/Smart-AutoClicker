# 路线录制与回放（实验功能）

这不是录屏或录制手指操作。软件通过可见的 X、Y 数字坐标，或小地图中稳定的道路特征来定位，将走过的地点保存为路径点；回放时读取当前位置，向下一个路径点移动，确认到达后再继续。两种模式都只读取屏幕，不读取游戏内存。

本功能属于开发分支新增功能，旧正式版不包含入口。第一次请在安全、空旷、不涉及购买的地图上测试一小段路线。

## 适用范围

- **数字坐标模式**：有可见的整数 X/Y 坐标，两个数字可以分别框选，数字区域的位置不随位数变化而明显移动。
- **小地图视觉模式**：地图布局固定，小地图方向和缩放固定，玩家标记始终在框选区域中心，道路随走路平移。画面需有足够独特的道路／墙体特征；重复房间、大片空白和严重遮挡可能无法定位。不适用于标记在静止整张地图上移动的布局。
- 地图有固定名称或图标，可用来核对当前地图。
- 点击地面模式：镜头跟随角色，角色脚下在屏幕上的位置基本固定。
- 摇杆模式：使用固定摇杆中心，在死区外短按并松开，按住时间 100～800 毫秒。动态摇杆、必须从中心起拖、惯性较强的游戏可能不适用。
- 回放使用相同分辨率、屏幕方向、镜头角度、缩放和移动速度。它不会读取游戏内存，也不会自动计算穿越障碍物的最短路径。

随机地图、旋转镜头、坐标被界面遮挡、坐标位置随排版变化、传送或战斗切换都可能中断路线。不能保证一次录制适用于所有游戏。

## 从哪里打开

1. 在首页启动一个**智能场景**，完成屏幕捕获和无障碍授权。
2. 不要开始普通场景的自动执行；若已运行，先停止。
3. 打开悬浮菜单中的场景编辑入口。
4. 在“场景”窗口左侧或底部点 **…（更多）**（位置随屏幕布局变化）。
5. 点 **路线录制与回放（实验功能）**。

路线独立保存在本机，不属于某一个事件。关闭场景编辑并不会删除已保存路线；目前不会随场景备份导出。可以手动回放，也可使用后文的“执行路线”动作，由智能场景条件触发。

## 第一次配置：数字坐标模式

先进入要录制的地图，在空旷处站稳。

1. 点“新建路线”，输入容易区分的名称，例如“长安入口到桥头”。
2. 选择“数字坐标模式”，点“框选 X 数字”：只框横坐标的数字，不要框逗号、括号或 Y 数字。
3. 点“框选 Y 数字”：只框纵坐标。留出数字变长的空间，并避免两个框重叠。如果 Y 随 X 位数变化大幅移动，这种坐标栏不适合当前版本。
4. 点“框选地图标记”：框选稳定的地图名称或图标，不要包含时间、人物或特效。
5. 点“截取地图标记”：配置窗口会隐藏，出现小悬浮条，完成后点“返回”。悬浮条不能挡住标记；若提示重叠，移动悬浮条后重试。
6. 选择“点击地面”或固定摇杆方式。
7. 点“选择角色脚下／摇杆中心”，将锚点放在对应位置。
8. 点“测试坐标（不会移动）”：检查悬浮条里的坐标是否与游戏一致。可以手动走几步，验证数字位数变化后仍能读对。点“结束”，再点“返回”。

如果提示模型缺失，先在应用设置的 OCR 模型管理中安装文字检测模型与拉丁文识别模型；数字识别使用拉丁文模型。

## 第一次配置：小地图视觉模式

适合部分安卓动作游戏的固定地图，不要求游戏显示数字坐标；不是“暗黑类游戏通用自动寻路”。

1. 新建路线，选择“小地图视觉模式”。不用填写 X/Y 数字区域。
2. 框选稳定的地图名称／图标，再点“截取地图标记”。此标记用于核对地图，不能选时钟、血条等变化内容。
3. 点“框选小地图”，框选以玩家标记为中心的地图区域，每边 96～512 屏幕像素。保持方向、大小与缩放不变，不要包含边框按钮。
4. 站在起点，点“截取小地图参考”。纯色或高度重复的地图会被拒绝。软件将参考位置记作内部坐标 `50000,50000`；这不是游戏坐标。
5. 选择移动方式及角色脚下／固定摇杆中心。
6. 点“测试小地图定位（不会移动）”，手动慢走一小段。2 分钟内需至少 20 次有效定位、有效率至少 80%，并移动至少 12 个标准化小地图像素。观察轨迹是否符合实际走向。
7. 显示“定位测试通过”后返回，**回到参考位置**，再做方向校准和录制。没通过时不允许自动移动；先重新选框或换更有特征的位置，不要强行降低安全门槛。

此模式不加载 OCR 模型。每帧只分析标准化为 192×192 的小地图灰度图，屏蔽中心玩家标记，与附近的已保存关键帧比较，不无限累加相邻画面的位移。运行条显示近期轨迹和道路特征匹配分数；分数不是“到达概率”，也不能保证没有走错路。

目前不检测玩家死亡、自动战斗或所有形式的传送。随机生成地图、旋转小地图、缩放变化和移动的玩家标记不在支持范围内。

## 校准两个方向

校准让软件知道“地图坐标改变多少”对应“屏幕向哪个方向点”。地图坐标不是屏幕像素，不能直接混用。

1. 站稳，点“选择校准 A 目标”，选择角色旁边一个无遮挡位置；摇杆模式则选择摇杆的一个偏移位置。
2. 点“执行校准 A（会移动）”。软件先读当前位置，然后执行一次短移动，再读取停下后的坐标。不要同时手动操作。
3. 完成后点“返回”。
4. 选择与 A 不同、尽量垂直的 B 方向，再点“执行校准 B（会移动）”。
5. 两次成功后显示“两个方向校准通过”，点“保存配置”。

校准目标与锚点距离需为 16～300 屏幕像素；实际地图位移需为 3～100 坐标单位。两个方向不能近似平行。如果碰到障碍、没有移动或坐标没读准，换空旷位置重试。改变锚点、移动方式或坐标区域会清除旧校准。

小地图模式请慢速、小幅校准，单次实际位移尽量在 3～15 个标准化像素内，过大的跳变会被安全拒绝。固定摇杆校准 A/B 选在有效半径内、死区之外，按住时间默认 500 毫秒；移动过快可先缩短时间再重校准。回放保持有效偏移，接近路径点时缩短按住时间。改变按住时间、移动速度或截取新的小地图参考后都要重新校准。

## 录一条路线

1. 回到希望作为起点的位置，站稳。
2. 点“开始录制新路线”。**等悬浮条显示“正在录制”且坐标正确，再开始走。**
3. 正常从起点走到终点，拐弯处不要走得太快，不要中途传送或切图。
4. 在终点站稳，点“结束”，看到完成提示后点“返回”。
5. 页面显示路径点数量和“路径录制完成”，已自动保存。也可修改名称后点“保存配置”。

录制期间不会自动移动角色，不保存整段视频。每隔约 400 毫秒尝试读取新画面，实际采样速度取决于设备识别耗时；移动约 3 个定位单位保存一个点。视觉模式的单位是标准化小地图像素。

每 5 秒保存一次未完成草稿。坐标或地图连续 5 秒无法确认会结束录制并保存草稿；进程异常退出最多丢失最近一次检查点之后的数据。草稿不能回放，需重新录制。每条最多 2000 个路径点、视觉模式最多 32 张灰度关键帧；每个路线文件最多 2 MiB，本机最多 50 条路线，达到限制时不会自动删除旧路线。长路程请分段录制。

重新录制创建新路线，不覆盖旧路线；不需要的路线可在页面底部载入后删除。

### 已录制，为什么还不能回放？

**“录制完成”只表示路径点已经保存，不代表方向校准也完成了。** 例如列表显示 18 个路径点，但上方仍是 `A:— B:—`，就需要补做两个方向的校准。

1. 在“已保存路线”里点想使用的路线。选中行会高亮并显示“✓ 当前载入”，底部会显示“已载入……”；先确认没有选错路线。
2. 查看“3．录制与回放”下方的待完成项。点“查看回放前待完成项”也会弹出缺少的设置，不会让角色移动。
3. 如果缺校准，到“2．移动方式与方向校准”中，先“选择校准 A 目标”，再“执行校准 A（会移动）”，结束后返回；然后选择另一方向的 B 目标并执行 B。
4. 已完成的路线在 A/B 校准都成功后会自动保存新校准，**保留原路线与路径点，不需要重新录制**。看到“两个方向校准通过”和“回放配置已就绪”后，再回到原录制起点回放。

底部状态栏会持续显示载入、保存、校准及运行结果，滚动页面也能看到。保存／载入期间显示进度并暂时防止重复点击。失败会说明待完成项或运行原因，不要靠反复点击尝试绕过校验。

补校准与更换定位方式不同：切换数字／小地图模式、重新截取小地图参考等会改变定位基准，不能直接沿用旧路径。请按界面提示重新录制。

## 回放与暂停

1. 打开相同地图，回到录制起点附近并站稳。
2. 打开路线页面，在“已保存路线”中点选目标路线。
3. 确认显示“回放配置已就绪”，点“开始回放”；若按钮显示“查看回放前待完成项”，先按提示补齐设置。
4. 软件按顺序接近路径点，每个点需要两次有效画面确认；到终点自动结束。

起点和终点**不需要一样**。例如录制 `(100,100) → (110,110)`，录完站在 `(110,110)` 时不能直接回放；需要手动回到 `(100,100)` 附近。数字模式会在路线页面显示保存的起点与终点。

如果提示“当前位置不在路线起点”，悬浮条会保留当时识别到的坐标，并显示“需返回”的位置、距离和允许范围。先手动回去、站稳，再点“复查继续”；它会清除旧定位缓存，重新确认后回放，不会自动从终点穿过障碍赶回起点。“路径点：0”表示本次回放还没通过第一个点，不是已保存的路线没有点。真正无法识别时才显示“未识别”。

框选 X、Y、地图标记和小地图时，窗口使用白色粗边框、深色描边和四边常驻圆形手柄。拖边框／手柄调整对应边，拖框内移动整个选区；点确认保存，点取消不修改。再次打开会恢复该路线自己的选区，不会受之前编辑的事件条件影响。

悬浮条上的“暂停”会阻止后续移动；已经发送给游戏的点击可能让角色继续走到该次点击目标，暂停不能撤销游戏自身的寻路。固定摇杆当前短按最长 800 毫秒后松开，不保证按下暂停的同一瞬间角色停止。“继续”会重新读图，“结束”退出本次回放。关闭悬浮条也会取消任务。

悬浮条角落的小圆点表示采样活动，也帮助完全静止的画面产生新的屏幕捕获帧；暂停和结束后不再闪动。不会通过重复使用旧截图来凑够到达确认次数。

回放中以下情况会暂停或停止：

- 起点距离过远，或暂停期间角色被移动到离原位置很远的地方。
- 地图标记或坐标连续 3 秒无法确认。
- 15 秒没有接近当前路径点，或单个路径点等待超过 60 秒。
- 目标位置与悬浮条、地图标记、坐标区域重叠，或系统拒绝执行手势。
- 屏幕分辨率、方向改变，屏幕捕获停止或权限/服务不可用。

恢复时先排除提示的问题，再点“继续”；如果镜头改变、发生传送或换图，应结束本次回放，不要反复强行继续。**独立路线测试与普通场景执行互斥**，避免两套逻辑同时点击；场景内的“执行路线”则在动作队列中顺序运行。

## 在智能场景里调用路线

1. 先在路线页面完成定位测试（视觉模式）、方向校准和录制，保存路线。
2. 回到智能场景，打开一个事件，进入“动作”，点 **＋ → 执行路线**。
3. 选择本机已完成的路线，设置总超时（5～3600 秒，默认 300 秒），点“保存配置”，再逐层保存事件和场景。
4. 给主事件设置地图入口图标等可靠条件。角色需位于这条路线的录制起点附近；条件满足后移动，到终点后执行下一动作。

例如：`识别入口 → 执行路线 A → 调用开门子流程 → 等待门打开 → 执行路线 B`。战斗或交互应在分段路线之间安排，不会边走边自动判断如何战斗，也不同时注入移动与攻击的多点触控。

路线缺失、起点不符、定位丢失、卡住、手势失败或超时会明确失败并停止场景，**不会继续执行后面的点击**。可从运行历史看该动作结果。场景调试暂停时不再发起后续移动，继续后重新确认位置；动作总超时包含调试暂停时间。

场景备份只包含路线 ID，不包含路线文件。换设备导入后，必须在新设备录制／配置路线并重新选择，不能直接使用旧设备的路线引用。

## 建议的验收方式

先用一条短 L 形路线验证：站在起点 → 向右走一小段 → 转向走一小段 → 结束。回到起点回放，检查转弯与终点；接着测试暂停、遮挡坐标、换图和靠近障碍时是否安全停下。短路线通过后再录制长路线。

代码中的模拟执行测试不能代替真实游戏验证；字体、坐标栏排版、镜头和移动方式都需要在目标游戏中确认。

本次已完成的自动化及 Google 官方模拟器测试，见 [Android 路线功能验证记录](route-android-validation.md)。
